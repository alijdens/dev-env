# redact-secrets

Replaces secret values in every tool result with `[REDACTED:NAME]` before the model reads them, so a `cat .env`, a `printenv` or a stray `secrets get` doesn't put a secret in the context (and the transcript). Each redacted result ends with a note telling the model not to print secrets and to use `secrets has NAME` / `secrets list` instead.

It hooks `session.append` for tool results, so it covers every tool (Bash, Read, Grep, MCP...) and subagents too. The matching is done by `secrets redact` from the `secrets` CLI (`features/core/bin/secrets`, on `PATH` through `install.sh`): the text goes to its stdin and comes back redacted, so the values stay in that process and the plugin never holds them.

What counts as a secret is best effort, decided by `secrets redact` from the variable's name: a value is redacted when the name has `SECRET`, `TOKEN`, `PASSWORD`, `PASSWD`, `PASSPHRASE`, `CREDENTIAL` or `APIKEY` in it, or `KEY` or `PASS` as a whole `_`-separated word (so `API_KEY` and `AWS_KEY_ID` match, `MONKEY` and `KEYBOARD_LAYOUT` don't), unless it also looks like config (`*_PATH`, `*_FILE`, `*_DIR`, `*_TTL`, `*_LENGTH`, `*_PREFIX`). Values under 6 characters are left alone as a floor, so something like `TOKEN_LENGTH=8` can't replace every `8` in the output. The values come from the environment of the session, the env files of its working directory (`.env`, `.env.*` except placeholders like `.env.example`, `.secrets`), and any files listed in `$SECRETS_REDACT_FILES` (`:`-separated) in the environment Claude Code starts with. The name patterns, the exclusions, the minimum length and the file patterns are settings of the CLI, in `~/.config/secrets-cli/config.json` or the file `$SECRETS_CONFIG` names; `secrets --help` has the format and the defaults. The password of any `scheme://user:password@host` URL is masked wherever it appears (`postgres://app:[REDACTED:url-password]@db/main`), whatever variable it came from; the rest of the URL stays readable. Out of scope on purpose: values of other names (a webhook URL, say, unless you add `*WEBHOOK*` to the names), encoded or split values, and anything the model derives from a secret. It also means a `Read` of `.env` shows the secret lines redacted, so editing those lines by hand has to happen outside the session.

If `secrets redact` can't run (the CLI isn't on `PATH`, e.g. `install.sh` hasn't run), results are stored unredacted and a toast says so once per load: failing closed would make every tool unusable.

Install: `ai-workflow/install.sh`, like the other plugins of the repo. Develop: `claude plugin validate .` and `claude plugin test .`; the CLI itself is tested with pytest (`features/core/tests/test_secrets.py`).
