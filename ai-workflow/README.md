# ai-workflow

Centralized, tool-agnostic instructions for AI coding assistants (Claude Code, Codex, ...). Edit once here, `git pull` on any machine, and every configured tool picks up the change.

## Layout

Everything installable lives in a feature under `features/`, one directory holding all its parts, so it's clear what belongs together and a feature is installed or removed as a whole:

- [`features/core/`](features/core) — always installed. `AGENTS.md`, the general instructions installed as each tool's global config file; `docs/`, the docs it loads conditionally (`pull-requests.md`, `planning.md`, ...); `bin/pull-pr-description`; `shell/git-push-reminder.sh`, which reminds to update the PR description after a `git push`; and the [`pending-items`](features/core/plugins/claude-code/pending-items/README.md) Claude Code plugin.

A feature's parts are found by name, and all are optional:

| Part | Rendered to | Installed as |
|---|---|---|
| `AGENTS.md` (core only) | `AGENTS.md` | each tool's global instructions file |
| `docs/` | `docs/` for core, `docs/<feature>/` otherwise | `~/.<tool>/docs` |
| `skills/<skill>/` | `skills/<skill>/` | `~/.<tool>/skills/<skill>` |
| `bin/` | `bin/` | on `PATH` through `env.sh` |
| `shell/*.sh` | `shell/` | sourced by `env.sh` |
| `plugins/claude-code/<plugin>/` | `plugins/claude-code/<plugin>/` | `~/.claude/skills/<plugin>` |
| `tests/` | — | run by `pytest ai-workflow/tests ai-workflow/features` |

Two features shipping the same skill, command, snippet or plugin name fail the install instead of one replacing the other.

The rest:

- `install.sh` — renders the selected features into `.rendered/`, symlinks the rendered copies into each tool's config directory, makes `~/.zshrc`/`~/.bashrc` source the rendered `env.sh`, and installs git hooks that re-run it after pulls and checkouts on the default branch. `AI_WORKFLOW_HOME=<dir>` installs into `<dir>` instead of `$HOME` (no hooks), for trying it out.
- `tests/` — pytest suite for `install.sh`, which drives it against a throwaway home. It and the features' tests run in the `ai-workflow tests` GitHub Actions workflow.
- `.rendered/` — generated by `install.sh`, gitignored. Holds the rendered copies tools are actually symlinked to, plus `features`, the installed selection. Tools never see the working copy, so switching this repo's branch or pulling on a feature branch doesn't change what a running agent uses; see "Pinned installs" below.

## Installing

```sh
./install.sh                     # all tools; the features installed last time, or all on a first install
./install.sh claude              # only for Claude Code (also codex, agents)
./install.sh --features a,b      # core + features a and b; replaces the installed selection
./install.sh --features none     # core only: unlinks everything the other features installed
./install.sh --list              # features, and which ones are installed
```

This creates:

| Tool             | Symlinked to                                           |
|------------------|--------------------------------------------------------|
| Claude Code      | `~/.claude/CLAUDE.md`, `~/.claude/docs`, `~/.claude/skills/<skill>`, `~/.claude/skills/<plugin>` |
| Codex            | `~/.codex/AGENTS.md`, `~/.codex/docs`, `~/.codex/skills/<skill>`    |
| Agents (generic) | `~/.agents/AGENTS.md`, `~/.agents/docs`, `~/.agents/skills/<skill>` |

Re-running is safe: existing correct symlinks are left alone, and any pre-existing real file/dir is backed up (`*.bak.<timestamp>`) before being replaced. Skills and plugins are linked one by one, so ones installed from elsewhere stay in the same `skills/` dir; links to ones removed from this repo or from the selection are cleaned up, for every tool.

### The `{{AI_WORKFLOW_DOCS_DIR}}` placeholder

`AGENTS.md` and the skills never hardcode an absolute path to the docs, since this repo can be cloned anywhere. Instead they use the literal placeholder `{{AI_WORKFLOW_DOCS_DIR}}`. `install.sh` never edits the tracked files in place (that would conflict with `git pull`); instead it renders copies into `.rendered/` with the placeholder substituted for this checkout's actual `docs/` path, and symlinks tools to those rendered copies. If you ever see the literal `{{AI_WORKFLOW_DOCS_DIR}}` text in a tool's loaded instructions, it means files got linked in directly instead of through `install.sh` — re-run `install.sh`.

### Pinned installs

After editing anything under `features/`, re-run `install.sh` to refresh the rendered copies. Pulls and checkouts do this automatically through the `post-merge`, `post-checkout` and `post-rewrite` hooks, which run `install.sh --refresh` for the tools and features already installed, but only while the default branch is checked out: a feature branch of this repo may lack a skill or a command, and an agent run started an hour ago must keep the commands, docs, skills and plugins it started with. On a feature branch, run `install.sh` by hand when you want to try its version. Existing hooks that aren't ours are left alone. The render builds the whole tree and swaps it in, so a session starting mid-render sees the old copy or the new one, never half of either.

Cursor is intentionally not included — it has no global instructions file, only per-project `AGENTS.md`/`.cursor/rules` or UI-managed User Rules.

## Content policy

Everything under this directory must stay generic and shareable: no personal information, company/employer names or specifics, internal tool or system names, credentials, tokens, or any other private context. Treat it as if it could be published publicly. When adding or editing a doc here, keep it scrubbed of anything that only makes sense in one particular company/team/project — that kind of context belongs in a repo-level doc instead, which these files already say takes precedence when it conflicts.
